# 📋 체크리스트: 데이터 관리 고도화 (증분 수집 및 만료 정리)

## 1. 개요
현재 수집기(`collector.py`)는 신규 데이터를 업데이트하는 방식이나, 이미 종료된(만료된) 매물을 정리하는 로직이 부족합니다. 이를 보완하여 DB를 최신 상태로 유지하고 프론트엔드에 유효한 매물만 노출합니다.

## 2. 작업 단계

### [ ] Step 1: DB 스키마 확장 (Migration)
- [ ] `onbid_items` 테이블에 `bid_end_date` (입찰 종료일) 컬럼 추가.
- [ ] `onbid_items` 테이블에 `is_expired` (만료 여부) 컬럼 추가 (기본값 0).
- [ ] `backend/init_db.py` 수정 및 실행.

### [ ] Step 2: 수집기(`collector.py`) 고도화
- [ ] 데이터 저장 시 `cltrBidEndDt` 값을 추출하여 `bid_end_date`에 저장하도록 수정.
- [ ] `mark_expired_items()` 함수 구현: 현재 시간과 비교하여 종료된 매물의 `is_expired` 플래그를 1로 변경.
- [ ] 수집 메인 루프 마지막에 만료 정리 로직 추가.

### [ ] Step 3: 익스포터(`export_data.py`) 수정
- [ ] `items.json` 생성 시 `is_expired = 1`인 매물은 제외하도록 SQL 쿼리 수정.
- [ ] 만료된 매물이 프론트엔드 정적 생성 대상에서 빠지도록 보장.

### [ ] Step 4: 검증 및 테스트
- [ ] 수동 실행 후 DB에서 `is_expired` 플래그가 정상 작동하는지 확인.
- [ ] `items.json`에 만료된 매물이 없는지 확인.
- [ ] `cron_sync.sh`에 변경 사항이 잘 반영되는지 확인.

## 3. 리스크 및 주의사항
- **날짜 포맷**: 온비드 API의 날짜 형식(`YYYYMMDDHHmm`)을 정확히 파싱하여 SQLite의 날짜 비교 로직과 맞추어야 함.
- **데이터 보존**: 사용자가 "지우는 것"을 요청했으나, 분석 이력 관리를 위해 삭제보다는 `is_expired` 플래그 처리를 권장함 (추후 재등장 매물 추적 가능).
